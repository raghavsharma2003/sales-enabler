# Azure Personal Voice enrollment

The Agents conversation panel accepts a speaker's own Azure verbal-consent WAV and separate 30–90 second speech WAV. Server code validates 24 kHz, 16-bit, mono PCM, stores uploads under ignored `data/voice-clones`, and uses the 2026-01-01 Azure Custom Voice API. The browser receives only enrollment status, never provider IDs, speaker profile IDs, key, or audio paths. The enrolled speaker must be the signed-in owner; another tenant or member cannot fetch or revoke the record.

Set `AZURE_PERSONAL_VOICE_LIMITED_ACCESS_APPROVED=true` only for an approved resource, plus `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`, and `AZURE_PERSONAL_VOICE_PROJECT_ID` in the private server environment. `AZURE_PERSONAL_VOICE_COMPANY_NAME` is an optional prefill; each enrollment requires the exact company name spoken in that speaker's Azure consent recording. The region is used to construct the fixed `https://<region>.api.cognitive.microsoft.com` origin; no client URL is accepted. Use an existing approved Personal Voice project. The current Azure OpenAI Realtime resource and key do not establish Speech access. Keep these secrets outside Git. Speech profile creation and hosting can incur separate charges; confirm grant applicability and limits before real enrollment. The UI requires an explicit cost acknowledgement and the speaker's authorization.

Submit first creates the Azure consent resource. The authenticated, same-origin POST refresh checks its status; after success it posts the audio sample to create the Personal Voice. The GET status route is read-only. Refresh again until `ready` or `failed`. Asynchronous operations are not compressed into a five-second poll. If submission has an uncertain result, the record stays `reconcile_required` and is never automatically retried. Revoke first fences the local profile and removes local private audio, then deletes both Azure Personal Voice and consent resources (404 is idempotent). Failed provider deletion stays `revocation_pending` for retry, even if enrollment configuration is disabled; the Speech key and region are still required. The local SQLite and private filesystem must be backed up/hosted together in any deployment; ephemeral serverless storage is not suitable for this enrollment flow. There is no automatic background reconciler yet.

For a ready profile, set `AZURE_PERSONAL_VOICE_BASE_VOICE` to a supported fixed-version base voice from Azure's `BaseModels_List` for the approved resource (for example `PhoenixV2Neural` only if that resource lists it). The operator can request a short paid Speech preview. The owner-scoped route checks Azure's current profile, then sends escaped SSML with the server-only `speakerProfileId` to the region's Speech TTS endpoint and returns bounded WAV audio. Each click can incur synthesis charges. The existing Azure OpenAI Realtime calls still use their configured stock voice; Voice Live integration needs separate testing on an approved resource.
