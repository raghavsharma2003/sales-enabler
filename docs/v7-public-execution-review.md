# v7 public execution adversarial review

Reviewed 27 September 2026. **Initial review: all three confirmed findings are fixed; six independent adversarial regressions and the combined 36-test public suite passed.** The later interruption follow-up below is also closed. Scope: the public deployment registry, anonymous session capabilities, text generation, WebSocket voice gateway, protocol and transcript provenance. This is an offline source and regression review, not a live Azure, production ingress, microphone or audio-quality evaluation.

## Confirmed findings

1. **P2 — disconnect during voice claim strands the session.** The bridge originally finalized only when `stop()` observed `ownsSession`. A disconnect while the durable claim was awaiting completion made `stop()` see false. Authentication subsequently acquired ownership and consumed a nonce, then returned at its late stopped-state check without finalization or closing the capability. The session continued to occupy its concurrency slot until expiry. The deterministic regression suspends the claim, disconnects, resumes the claim, and checks no provider connection and exactly one capability close. Original result: zero closes instead of one.

2. **P2 — cancelled response completion clears a newer voice response.** The bridge originally handled every `response.done` by clearing one global `responding` flag and ignored `response.created`. In normal event order, visitor interruption sends cancel for the greeting and immediately requests the next response; the cancelled greeting's completion then clears the new pending response. Its subsequent creation does not restore the flag. The next visitor message therefore creates another response without cancelling the active one, risking a provider active-response error and conversation interruption. The deterministic regression delivers those ordered events and checks two cancellations before the third response request. Original result: one cancellation instead of two.

3. **P2 — republishing retains concurrency occupied by invalidated sessions.** With concurrency set to one, issue a capability, pause the deployment, and publish it again. The old capability correctly fails revision validation, but a new issuance receives HTTP 429 because the slot counter still includes the old active row. The authority-dependent close path also cannot release that invalid capability. A resumed assistant therefore remains unavailable until its prior expiry, potentially ten minutes. The deterministic regression performs this sequence with no provider calls and requires a fresh capability. Original result: `All public conversation slots are in use.`

Gateway fixes were made by the public voice bridge task; the registry fix was made by the deployment registry task. This review only changes `tests/v7-public-review.test.ts` and this document. Both gateway regressions pass after the bridge fixes: finalization is scheduled once even when ownership arrives after disconnect, and bounded response slots preserve each provider response's identity and cancellation state. The gateway also now ignores stale cancelled audio and terminal events, including cancellation before `response.created`.

The registry now counts only current-revision capabilities for concurrency, while keeping daily and network counters intact. Capability cleanup authenticates the token and exact stored origin independently of deployment revocation; it returns no context or inference authority and accepts repeated cleanup. The independent pause/publish regression and the owner's foreign-origin, daily-budget and stopped-cleanup checks pass. Existing voice connections still stop through the existing two-second authority recheck or hard expiry; publication is not a synchronous distributed socket-termination mechanism, so a prior voice stream may briefly overlap a newly issued current-revision session during that bounded recheck window.

## Additional verified boundaries

- A deliberately interleaved session issuance between the concurrency-count read and budget reservation is rejected by the issuance epoch fence. One active capability remains with the concurrency limit set to one and independently high daily/network limits.
- Six simultaneous uses of the same nonce produce exactly one successful consumption and one recorded turn.
- Public text inference receives the selected company source and published task instructions, excluding private unselected company source, customer and GroupAI sentinel records.
- Browser-submitted history cannot use the `public_voice` source. Forged public session identity, verified caller identity and server-capture provenance fields are rejected or omitted; the ordinary browser transcript keeps its explicit unverified browser provenance.

Static inspection also found explicit Azure hostname/path validation and disabled redirects; gateway tokens travel in the first WebSocket frame, not the URL; bounded client message schemas do not expose provider instructions/tools/role selection; public source/release/publisher authority uses transactional fences; and time, input-audio, output-audio, transcript, output-token and response-turn limits are present. Existing focused public tests exercise these paths further. Host CSP/frame ancestors and ingress header behavior are coordinated separately with the root task and are outside this report's runtime verification.

## Reproduction

Run `node --import tsx --test tests/v7-public-review.test.ts`. The initial run recorded three passing boundary tests and two failing gateway regressions. The added registry regression also failed before its fix. Final independent verification passes **6/6**, with **36/36** passing in the combined review, deployment, gateway, protocol and service suites. Context validation passes with 115 nodes, 124 edges and 50 events. All fixture identities and provider settings are fictional; SQLite uses memory and review sockets are in-process fakes (the existing gateway suite uses a local fake WebSocket provider). No external provider request, credentials inspection or full build was performed.

## Playback interruption follow-up

A subsequent narrow review of `playback.ts`, the browser adapter and the gateway found three further interruption-history defects. All are fixed by the voice bridge owner and independently verified:

- A wholly unheard later provider item whose creation event arrived after cancellation was silently dropped locally but remained in provider history. The gateway now deletes new item IDs belonging to the cancelled response, retaining known heard/partial items and ignoring duplicate creation events.
- A drained browser queue lost its heard offset while generation continued. An unheard suffix could cross the interrupt in either direction, or arrive as a new item. The browser now sends a bounded last-heard watermark; the gateway retains it, trims only a real unheard suffix, and removes wholly unheard later items. The regression covers both transport orderings and a late new item with no extra suffix on the heard item.
- Subtracting audio-clock timestamps could turn a fully heard 100ms segment at clock 4s into 99.99999999999964ms. Flooring that value incorrectly truncated heard history at 99ms. Completed segments now accumulate integer PCM sample counts; a tiny tolerance repairs floating-point noise in partial offsets without rounding genuine partial playback up.

The follow-up adds three independent regressions to the same review file, bringing it to **9/9** passing. The combined review, playback, gateway and protocol suites pass **35/35**. Cross-response item ownership, arbitrary client item rejection, cancellation replay, late frame suppression, known-item preservation and integer partial offsets remain covered. This verification used in-process/local fake providers only; live audio quality, actual provider behavior and browser artifact deployment remain root-task checks.
