# Calling workbench

The Agents workbench supports a direct test call from an unsaved draft. The call is an internal operator preview and starts from a server-issued preview connection record; saving or publishing the agent is not required.

1. Open **Agents** and select Maya, choose a feedback/lead-qualification preset, or create an agent. For a blank agent, fill the Objective tab's name, role, objective and escalation fields too.
2. Edit **System prompt** and **Opening message**. Configure languages, relationship memory and approved knowledge in their tabs. These current editor values are compiled into the draft preview context.
3. Choose the **Voice profile**. **Azure workspace voice** is the default and the only paid inference route. **Maya original · Gemini Despina** is an explicit source profile for Gemini Live 3.1 (`gemini-3.1-flash-live-preview`) and uses a recovered, allowlisted key from the existing free pool; it does not change Azure's default or create a fallback. If that profile is not explicitly configured, the app fails closed.
4. Open **Test call**. Choose company knowledge only or an optional customer context. Choose **Microphone** to speak, or **Listen & type** to hear the agent and type replies without microphone permission.
5. Check the AI-call consent box, then select **Start test call** or **Start voice preview**. In microphone mode allow the browser's microphone permission; in Listen & type send a reply using the input that appears once connected.
6. End the call and review **Transcript**, **EmotionalOS**, **RelationalOS** and **Context**. Select **Save internal preview** to retain the transcript and server-computed runtime evidence, then open **Conversations → View tested prompt** to review the original draft. Download and discard are also available.

Saving the agent retains future edits. Capture version → Test lab → Releases is the separate publication workflow. A draft preview cannot count as published campaign evidence. Selecting a customer loads approved context for this internal test and does not verify a caller's identity.

The verified paid route uses the existing Azure OpenAI Realtime resource with `gpt-realtime-2.1-mini` and `marin`; it is the default and only paid route. Two completed browser **Listen & type** calls received real Azure provider audio and produced saved draft-linked transcripts. **Integrations → Check connection** checks Azure short-lived-token provisioning only; it does not open audio or measure speech. OpenAI remains an inactive alternative. The Maya Gemini adapter is a real, explicitly selected path: one recovered free-pool key produced a 4.92-second Live response and a separate 4.04-second TTS render with Despina, and the browser **Listen & type** path later passed after ordered binary string/Blob/ArrayBuffer frame decoding was fixed. That bounded Maya browser check ran for about 92 seconds with seven entries (the opening greeting plus three typed turns and their replies) and produced Hinglish responses. It establishes a working bounded path, not exact prompt compliance, a broad quality result or competitive superiority.

The transcript is saved only on request and is an operator-submitted artifact, not a provider-signed call record. New draft calls derive their input mode from the issued preview snapshot; older saved records may have no mode label. Released calls use a server-issued connection record. The server recomputes the relational runtime from the authorized saved transcript and context when the preview is saved, so client-submitted runtime evidence is not trusted.

The source-derived runtime carries repair hysteresis, language, honorific, pacing, moment/continuity and quoted-evidence handling through live calls and saved preview evidence. In the bounded Maya check, RelationalOS moved from `open` to `repairing` to `repaired` after two distinct caller confirmations; the saved preview showed four server-recomputed state changes. Azure updates its session instructions after a finalized caller turn. Gemini receives that guidance as best-effort context for a subsequent turn; it is not a live system-instruction update and may take effect after a response already in progress. The exact opening was spoken only as the first sentence, and an earlier bounded one-question check requested two fields. These observations are explicit quality follow-up, not proof of exact instruction compliance or superiority. EmotionalOS cues and RelationalOS preferences/open commitments remain bounded business adaptations with review and revocation rules; they do not claim the companion engine or persona cloning.
