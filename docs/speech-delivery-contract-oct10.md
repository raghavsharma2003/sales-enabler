# Bounded speech delivery contract — 10 October 2026

`lib/voice/speech-delivery.ts` owns the shared, deterministic contract. It is delivery configuration, not a new voice model, emotion classifier, sentiment score, or evidence of acoustic quality.

An agent may contain `speechDelivery: { version: 1, pace: 'standard' | 'unhurried', adaptToRequests: boolean }`. All three properties are required when the object is present. Unknown fields, unknown versions, null and coerced values are rejected with a fixed client-safe validation error; the agent parser maps it to HTTP 400. Absence remains absence in parsed and serialized old configurations, preserving old snapshots and hashes. Its effective behavior is standard speed 1 with adaptation disabled. Explicit configurations remain explicit, including standard/no-adaptation settings. The only supported configuration is the Azure `provider-default` voice profile; a provided speech-delivery profile on `maya-despina` is rejected. Runtime Azure capability enforcement remains the adapter's responsibility.

`resolveSpeechDelivery(profile, entries)` accepts the current ordered committed final transcript, whose entries contain `id`, `role`, and `text`. The caller must never pass interim ASR, tentative sidecar transcripts or preparation text: this minimal entry shape does not establish finality. Exact `user` entries alone can supply request authority. A decision has speed `1 | 0.9`, pace `standard | unhurried`, basis `agent_default | caller_request`, and a `sourceTurnId` only for a caller request. There are no arbitrary numeric speeds. The resolver is pure and rebuilds the decision on every invocation; repeated IDs use their last occurrence. Callers must supply the revised sequence after replacement or deletion and must not merge in a cached old decision.

With operator adaptation enabled, a finite grammar recognizes complete explicit English, Hindi and Hinglish slow/normal requests, such as “please speak slowly”, “could you slow down a bit”, “थोड़ा धीरे बोलिए”, “thoda dheere bolo”, “speak normally”, “go back to normal speed” and “normal speed pe bolo”. Case, whitespace, courtesy words and terminal punctuation are tolerated. A matched request persists across subsequent unrelated turns until another explicit recognized request; normal resets to speed 1 even when the agent default is unhurried. Unknown or ambiguous wording preserves the last choice. Full-request matching rejects quotations, negation, third-party reports, hypothetical requests and compound contradictory instructions instead of stripping their context to discover a keyword. This intentionally conservative grammar is not a general multilingual intent model.

Emotional self-reports, requests for brevity, inferred confusion, descriptive “too fast” comments, and requests for unsupported rates do not map to speech speed. Assistant messages never set or reset pace. This contract supplies bounded intended delivery; exact provider acknowledgement, between-turn application, active-response guards and receipts belong to the consuming runtime. An accepted configuration is not proof of perceived pace or better voice quality.

The v1 grammar also accepts the complete direct form “explain this/that/it/the next step(s) slowly”, optionally followed by “one point at a time”. It may have the exact first-person prefix “I'm feeling overwhelmed.” (also “I’m” or “I am”). This admits the proof scenario “I'm feeling overwhelmed. Please explain the next step slowly, one point at a time.” and its plural ASR variant. Only the explicit slow instruction sets pace; the self-report alone does nothing. This is an anchored full-utterance allowance, not keyword extraction or general emotion adaptation. Negated, quoted, reported, conditional and third-party variants remain outside this form.

Offline verification is in `tests/speech-delivery.test.ts`: strict values/errors, unchanged legacy serialization/hash, provider-profile capability, both rates, opt-in behavior, English/Hindi/Hinglish direct requests, reset/persistence, contextual guards, revision/deletion and source-bound pure replay. No microphone, provider call, cloud mutation, Docker workflow or acoustic listening is required or claimed by these checks.
