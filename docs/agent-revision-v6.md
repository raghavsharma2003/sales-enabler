# Reviewed agent revisions

In **Voice agents → Improve with an instruction**, an operator can describe a behavioral change in ordinary language. This revises the saved agent configuration; it does not train or change model weights. The agent must first be saved, and the editor must have no unsaved changes. The request uses the current saved agent record, revision, and canonical config digest. The AI task router sends one bounded planning request through the configured Azure text deployment only. A stable client request ID is reused for the same attempt; **New attempt** deliberately changes it.

The server claims a tenant-scoped `platform:agent_change_proposal` before inference. A repeated request returns the saved result, while changed input with the same ID is rejected. A pending or uncertain AI result is not automatically retried. The model may return complete replacements only for `systemPrompt`, `openingMessage`, `responseStyle`, `objective`, and `escalation`. Unexpected fields or shapes invalidate the suggestion. The server parses the complete candidate with `parseAgentConfig`, keeps all protected fields identical, requires an AI-identifying greeting when one is present, keeps a human handoff option, and stores the exact before/after configs, digests and changed-field review. A complete system-prompt rewrite is shown in the before/after review instead of being rejected merely because it rephrases existing instructions.

Invalid output remains a saved invalid record and cannot be applied. An operator may explicitly **Recheck saved output** after server validation changes. Recheck reads the already-completed tenant-scoped Azure receipt and performs no new inference. It requires the same saved agent revision and digest, preserves the earlier validation error in proposal history, audits the transition, and produces a reviewable ready proposal only if the receipt passes every current validation rule.

The operator sees each changed field side by side and explicitly applies it to the mutable draft. Apply checks the original agent revision and digest, revalidates the saved proposal, then atomically updates the agent and marks the proposal applied with audit events. Concurrent edits fail with a regenerate message; repeated apply is idempotent. Applying a suggestion does not capture an immutable agent version, run a test, publish a browser release, launch a campaign, or alter an existing saved release. The operator can test the updated draft and use the existing capture, check, and publish gates separately.

The instruction is treated as an operator request, not as evidence of a customer statement or a change to company facts. This slice does not consume conversation analysis or claim source-backed learning. Tenant ownership and operator membership are checked server-side. Viewers can inspect saved suggestions but cannot request or apply them.
