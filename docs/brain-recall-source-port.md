# Grounded company-brain recall port

The Company brain question box retrieves current approved company evidence, asks the existing Azure `answer` task for a bounded response, and returns only answers with exact cited quotes. It is an internal staff tool. It does not use GroupAI private facts, customer memories, conversation transcripts, or external actions.

## Source and adaptation

Pinned source: `research-sources/html-portfolio`, `origin/main` at `3a9217981b27636745fc70ac490aacf9ef3f392d`. `api/memory.js` blob `f2ebfcf06913ad684e381d48d5de81442e83f54e`, specifically `recallTokens`, `rrfFuse` (`RRF_K=60`) and the scoped `opRecall` query/citation boundary. The source combines keyword, semantic and co-citation legs over Meera's person/agent facts. This port retains the deterministic reciprocal-rank score `1/(60+rank)`, a bounded result set, whole-word token matching and source IDs. It combines two independent lexical views: source title and source body. Deduplication is by exact chunk ID because company documents can share a title without being the same evidence. There is **no embedding or semantic leg** in this port; the UI says “Keyword search.” The source's dyadic salience, intimate relationship facts, cached call bundle and Google/OpenRouter fallbacks were not copied.

`lib/brain/retrieval.ts` reads only rows in the authenticated organization. Eligible sources are approved `platform:brain_source` records with their current revision, or `knowledge` rows created by a reviewed ingestion candidate whose source artifact, digest, exact quoted span, proposal decision and applied candidate still agree. Old free-form staff-authored `knowledge` lacks a review/revocation contract and is excluded here, even though the older internal staff voice context may include it. GroupAI audiences and contact memory are outside this company-wide search. Source text is split into exact 850-character windows with a small overlap, and title/body matches are fused into at most eight chunks.

`lib/brain/answer.ts` calls `runAiTask(user,{task:'answer',responseFormat:'json_object'})` only when at least one chunk matches. The task router uses the configured Azure text deployment, durable request claims and its token budget. The model sees selected chunk IDs, titles and text, with an explicit instruction that evidence is data. A citation is accepted only when its ID was selected and its quote is an exact 6–400 character substring of that chunk. Unsupported, malformed and uncited answers become an honest insufficient-evidence response. This check establishes quote provenance, not full semantic entailment of every answer sentence; factuality still needs evaluation with real questions.

Each saved `platform:brain_answer` has a user-scoped request ID, question hash, source binding hashes, selected quote spans and a digest of the searchable approved catalog. Before the answer is committed, cited rows are re-read and compared, and no-op compare-and-set checks run with the insert in one database transaction. A changed or revoked source cannot be silently committed. Replay checks all bindings and the current catalog before returning saved text; a new source invalidates even a prior empty answer. The UI rechecks before expanding a citation and when its window regains focus, clearing a stale response. The server does not expose a raw-source download route.

The `POST /api/brain/answer` endpoint requires a signed-in user, same-origin JSON request, a question of at most 1,000 characters and a short request ID. The component `components/brain-answer.tsx` is mounted in Company brain and uses text rendering for model output and quotes. AI answers cannot authorize bookings, messages, record changes or commitments.

## Verification and limits

`npx tsx --test tests/brain-retrieval.test.ts` covers tenant isolation, older relevant evidence, revoked sources, exact citation validation, replay after revocation, source change during model generation, reviewed ingestion lineage, and an empty-answer catalog change. `npm run typecheck` passes. Tests inject a fake answer runner; they make **no paid provider request**. The source repo was read only; no source tests or migrations were executed for this port.

Keyword search misses paraphrases with no shared terms. A future Azure embedding lane should be explicitly configured, metered and evaluated, while preserving the lexical path and pre-ranking authority filter. This local implementation stores source chunks in the existing entity store and scans current sources per question. Larger deployments will need a separate indexed chunk table, source-change invalidation and production database testing. The exact-quote check does not prove the answer's reasoning, so uncertain or conflicting evidence should remain visibly uncertain and be reviewed before customer-facing use.
