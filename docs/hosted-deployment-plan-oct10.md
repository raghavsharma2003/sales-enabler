# Reviewed Azure private-beta deployment plan — 10 October 2026

## Release decision

This package prepares, but does not perform, the hosted deployment. The approved boundary is the existing startup subscription and resource group only. It reuses only the audited shared Basic ACR, Log Analytics workspace, and ACS Email resources. It creates project-specific networking, Container Apps environment, runtime identity, Key Vault, PostgreSQL, budget, role assignments, and deletion locks. No Docker, WSL, local container, employer tenant, third-party inference, resource creation, key listing, provider call, image build, or deployment occurred while preparing it.

Current read-only access is sufficient for foundation resources: all ten required providers are registered; VNet, private DNS, Container Apps environment, managed identity, Key Vault, PostgreSQL, diagnostics and budget writes are permitted. The deployment identity cannot write role assignments or locks. The shared Basic ACR uses legacy registry RBAC; the identity can control ACR Tasks but has no repository data access. A separate human Owner pass must apply only `AcrPush` for the deployer, `AcrPull` and `Key Vault Secrets User` for runtime, `Key Vault Secrets Officer` for the deployer, and delete locks on the project database/vault. No subscription-wide assignment is requested.

The target remains absent: no sales-enabler environment, identity, vault, PostgreSQL server, app/job, or budget exists. ARM validation currently stops at `MaxNumberOfGlobalEnvironmentsInSubExceeded`: six environments exist subscription-wide, even though East US 2 reports two used against a regional limit of five. A managed-environment quota increase is required; unapproved shared environments must not be reused or deleted. The credit-summary API still returns 401. The user's declared approximately USD 4,000 grant and authorization allow preparation to continue, but do not prove balance or coverage.

## Artifacts

- `infrastructure/azure/prerequisites.bicep` creates the private foundation. It uses a `/27` subnet delegated to the v2 workload-profiles Container Apps environment, a separate `/28` PostgreSQL subnet, private DNS, public database access disabled, B1ms/32 GiB/no HA/seven-day backup defaults, Key Vault RBAC/soft delete/purge protection, a runtime identity, shared-workspace diagnostics, and a USD 150 alert budget.
- `infrastructure/azure/role-assignments.bicep` is the separate Owner-reviewed pass for four narrow roles and two delete locks. The normal deployment identity cannot apply it.
- `infrastructure/azure/main.bicep` deploys immutable application images. It now wires the finite organization inference allowlist, per-organization AI/voice budgets, `DATABASE_POOL_MAX=4`, Azure Speech secret/region, `/voice` and `/private-speech` WSS URLs, email verification, and the durable private-voice supervisor.
- `Inspect-Prerequisites.ps1` and `Inspect-Deployment.ps1` validate private ignored parameter files and run Azure what-if only. They reject placeholders, unsafe SKUs, missing email/Speech/supervisor dependencies, mutable image tags, non-WSS gateway URLs, oversized pools, and unbounded replica settings.
- `check-hosting-access.mjs` repeats the redacted ARM-only access audit. It reports booleans, counts, role names and HTTP status only; it never prints credentials, tokens, endpoints, names, resource IDs, keys, or response bodies.
- `Build-RemoteImages.ps1` accepts only an exact 40-character reviewed Git commit and the reviewed HTTPS GitHub remote. Without `-Execute` it only validates. With `-Execute` it uses ACR Tasks for `web`, `voice-gateway`, and `private-voice-supervisor`; it never invokes a local container engine.

All three Bicep templates compile cleanly with Bicep CLI 0.48.1. PowerShell/JSON/Node parsing and the live redacted access check pass. ARM validation reaches the Container Apps quota gate above; it performed no mutation. The application-owned supervisor image target, bounded database pool and live-stop correction are at `596b890` with 1,054 integrated tests and 32 focused shutdown checks passing; final production build/package verification remains root-owned.

## Deployment sequence

1. Freeze the exact final tested commit and ensure that commit is available from the reviewed remote. Do not build a dirty checkout or a branch-only label.
2. Request an East US 2 managed-environment quota increase that also clears the observed subscription-wide environment gate. Wait for approval and rerun ARM validation; do not reuse or delete other environments.
3. Copy the three example parameter files to ignored `*.local.json` files. Resolve shared ACR/Log Analytics names privately, confirm VNet CIDRs, and provide one billing-alert email plus the first UTC day of the deployment month.
4. Set the PostgreSQL administrator password only in the deployment shell, run `Inspect-Prerequisites.ps1`, and review what-if. Apply the foundation from Cloud Shell/controlled CI only after validation passes. The checked-in file must contain no password or runtime secret.
5. A human Owner runs `Inspect-RoleAssignments.ps1`, reviews the four assignments/two locks, then applies that separate template. Wait for propagation and require the redacted checker to report repository write plus runtime pull/vault access.
6. Populate the new Key Vault privately with: `database-url`, `connector-key`, `auth-lifecycle-key`, `public-session-key`, `azure-openai-key`, `azure-speech-key`, and `account-email-key`. Existing ignored configuration already holds approved Azure inference/Speech and stable app keys; do not request them again. The ACS key still needs secure placement. Require a private PostgreSQL URL with TLS verification.
7. After the final commit passes, run the remote-build script with `-Execute`. The first small build is the ACR Tasks availability probe. Stop on failure; never use local Docker. Resolve successful tags to immutable digests.
8. Run application what-if. Web/gateway default to zero-to-one replicas; the supervisor stays exactly one. All use a four-connection pool; readiness uses a separate one-connection probe. Keep optional workers off for the first hosted gate.
9. Apply web, supervisor, and gateway in single-revision mode. Require web readiness, gateway `/health`, a fresh supervisor heartbeat, exact HTTPS/WSS origins, Key Vault resolution, PostgreSQL TLS/schema access, and redacted logs before enabling any organization in `INFERENCE_ALLOWED_ORGANIZATION_IDS`.
10. Exercise one fictional invite/verification/reset flow through the existing Azure-managed sender, then one disclosed-AI Listen & type call. Confirm `/voice` and `/private-speech` origin rejection, durable stop, saved evidence, budget accounting, and zero credential exposure. Physical microphone, acoustics, interruption quality, and customer value remain separate gates.
11. Enable the automation worker only if scheduled beta execution is required. With pool size four, web + gateway + supervisor reserve at most 12 application connections when awake; automation raises that to 16, plus bounded probes/operations. Channel and learning remain off until their external-action and inference scopes are explicitly included. Scheduled Job conversion is still desirable for automation/learning cost, but the current always-on worker is the reviewed implementation.
12. Soak with fictional data for one business day. Alert on revision failures/restarts, gateway disconnects, stale supervisor/worker heartbeats, PostgreSQL CPU credits/connections/storage, log volume, and inference usage. Stop or resize on sustained pressure; do not raise replica maxima.
13. Perform PostgreSQL point-in-time restore to a new isolated server, run read-only integrity/readiness checks, and record measured RPO/RTO. Never restore over the running beta. Remove the temporary restore only after evidence review and after handling its delete lock deliberately.

## Rollback and remaining blockers

Preserve the prior three image digests and nonsecret parameter manifest. Roll back by redeploying those digests in single-revision mode; do not rebuild old tags. Database bootstrap remains additive `CREATE IF NOT EXISTS`, so image rollback does not reverse schema changes. Freeze schema for this beta and add versioned migrations before any later schema evolution.

Actual deployment is blocked by the Container Apps environment quota increase; a human Owner review/apply for narrow roles/locks; the final fully verified commit including the live-stop fix; private parameters and billing-alert address; secure PostgreSQL/ACS secrets; all three what-if reviews; remote build/digests; and hosted readiness, email, WSS, supervisor, soak, and restore evidence. Credit visibility remains a monitored limitation under the user's explicit grant authorization, not a reason to request supplied keys again.
