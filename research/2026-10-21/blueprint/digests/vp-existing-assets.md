# What VP already has to build on (inventory for the blueprint)

Read for this digest: context/DIRECTION.md, CLAUDE.md, AGENTS.md, context/STATE.md (head), package.json, the graph (asset.*, component.voicelab*, decision/rejected nodes), voicelab/ source (catalog.py, persona_v2.py, persona.py, calls.py, providers.py, phone.py, audio.py, app.py, README), the Relay-era code layout and docs, docs/harvest/se-audit.md and se-live.md, research/2026-10-20/voicelab/round1-review-and-v2.md. I read the lab code directly; I did not run it (no tests were run, no vendor or provider calls were made). Numbers below are quoted from repo files and carry the grade of their source.

## 1. Bottom line

1. **The one thing worth building on is the voice lab (`voicelab/`, about 2,900 lines of Python server plus 640 lines of browser client).** It is a working, deployed, prototype-grade runtime. It already has the pieces DIRECTION.md lists as "ported": adapters with measured price/latency metadata, combination identity, brief v2 with the agenda ledger, the guarded hang-up, turn-taking, the Plivo phone leg and the cost meter. All of this is `asset.voicelab.*` in the graph, status prototype, effort "port".
2. **The lab is a test bench, not a platform.** There is no tenant, no database, no contact or campaign object, no consent/DND handling, no dialer queue, no auth beyond one shared passcode, no tests beyond sims. Everything persists as JSON/WAV files on one VM (`voicelab/server/app.py` `Lab`, `DATA/calls/*/meta.json`, `spend.jsonl`, `memory/*.json`). It supplies the **call engine and the evidence discipline**; the blueprint must supply everything around it.
3. **The Relay build (`app/`, `lib/`, `components/`, about 31k lines of TS) is stale and must not shape the design.** The owner rejected the UX (2026-10-01) and the baseline (2026-10-15, `directive.2026-10-15.codex-baseline-stale`). The harvest verdict was REBUILD and carry forward about 12-15 mechanisms as concepts, re-implemented on a new schema (`decision.2026-10-15.rebuild-verdict`, status proposed; reversal condition: owner rejects it, and the owner's later "stale" judgement and the 2026-10-18/20 pivot to a Vapi-like self-serve platform point the same way).
4. **The scarcest reusable asset is the evidence base, not the code:** the `rejected.*` list (what failed, measured), the lab's rating data, and the inherited laws. The blueprint should start from them.

## 3. What the lab has measured (carry into the blueprint as evidence)

- Round 1: 65 calls (54 browser, 11 real phone), 33 rated, 4 testers. Best stack Gemini 3.1 Live 7.0/10 (n=2); Azure-voice stacks 1.5-4.5. Every stack's content was robotic and the cause was the brief (`research/2026-10-20/voicelab/round1-review-and-v2.md`). Small n; indicative only.
- Robotic signature (316 turns): 53% end on a question, 19% mention link/callback/advisor, median 22 words per turn, 21% re-state "I'm an AI".
- Brains on brief v2 (LLM judges): Gemini 3.8 Flash best (65/75 win rate) but its first token is about 2.0 s from India; Gemini 3.5 Flash-Lite 0.70 s; GPT-5.4 mini 0.96 s; GPT-6 Luna judged last (28/30) though the owner prefers it, unconfirmed by ear.
- First audio from India: MAI-Voice 2.1 Flash 425 ms, Gemini 3.8 Flash-Lite TTS 624 ms, Gemini 3.8 Flash TTS 772 ms, via OpenRouter about 2.1 s (non-streaming).
- Round-2 smoke reply gaps: 3.8 Live 0.8-1.6 s, Flash-Lite cascade 1.6-2.2 s, 3.8 Flash cascade 2.9-4.2 s. Browser-measured round-1 median 1.74 s (n=199).
- Cost: lab presets ran from about INR 0.94/min (gated Gemini ears + gpt-oss on Groq + Azure voice, from the research report) up to INR 4.2-5.7/min for Gemini Live. Gemini Live at about INR 2/min was rejected (`rejected.2026-10-19.gemini-live-at-rs2`).
- Not measured: any round-2 human rating; handset-end reply gap on phone; telephony network delay.

## 4. Relay-era build (`app/`, `lib/`, `components/`, `scripts/`, `tests/`, `docs/`)

**What it is.** A Codex-built Next 16.4 / React 19.3 / TypeScript workspace for "company operations": company profile, a reviewed company brain (PDF/DOCX/CSV ingestion with exact-quote review, cited Q&A), AI campaign plans, an agent studio with immutable versions and releases, public web/voice deployments, Telegram/WhatsApp agents, CSV customer intake, a connector vault with 19 adapters, team roles, and a campaign result extractor. Sizes (se-audit, `wc`): lib 22,008 lines in 172 files (voice alone 7,717), components 7,182 TS lines (9,649 total), app 1,928 TS lines with 72 API routes, tests 145 files / 20,745 lines, scripts 26 files, infrastructure/azure Bicep 925 lines.

**Evidence of quality.**
- Observed (se-live): it ran end to end on local SQLite and real Azure gpt-4.1-mini, signup to public chat, no 5xx, no horizontal overflow at 390 px. It was never deployed to a host.
- Tests: 1,153 passed at baseline (`evidence.2026-10-15.baseline-tests`), all unit/contract with mocked transports, no browser e2e, no Postgres, no live evals. About half of tests and 35% of lib are voice research tooling.
- Voice evidence there is thin: its best-evidenced stack (Azure Realtime WebRTC) was never tried with a real microphone; a live call showed repeated introductions and about 90-word replies.
- Phones: telephony was "planned" only. No outbound dialling anywhere in Relay.

**Why it is stale (do not let it shape the design).**
- Wrong product shape: a voice-agent studio plus a governance ledger, with heavy warning copy that treats the operator as an auditor (se-live).
- One JSON-blob `entities` table written by raw SQL from 44+ files, compare-and-set by full-JSON equality, no migrations, one org per user, hash-routed single page, 72-route action-string API, seven long-running processes (`rejected.harvest.17`).
- No contact/account/pipeline objects; the CSV import had nowhere to put Company/Country/Product columns; customer CSV leaked into company-knowledge extraction.
- Five voice stacks, four of them rejected elsewhere (S2S as the speaking agent, `rejected.harvest.01`); a Gemini free-pool path that breaks policy (`rejected.2026-10-20.free-key-rotation`).
- Azure-only assumptions superseded by `directive.2026-10-18.provider-open`.
- Visual identity: DM Sans, cool white with indigo (#5148ce), 13 px body, cards, left nav ("Quiet Operations Desk", `DESIGN.md`). Generic SaaS. The `/prototype` page (serif, warm palette, dark-green sidebar, terracotta; `asset.se-live.prototype-visual-concept`) is the best look in the repo but was simulated data.
- The README and docs describe a v4-v7 incremental story that no longer matches the direction; `docs/` has about 100 dated files. Trust `context/DIRECTION.md` over all of them.

**Concepts worth carrying (re-implement, do not import).** Each is listed in the graph as `asset.se-audit.*` or `asset.se-live.*`, tested locally but never in production:
- Evidence-span intake: source to passages to AI proposals with verbatim quotes to human approval (`lib/ingestion`, `asset.se-live.evidence-span-company-brain-intake`). Fits a "client just talks, we ingest their data" flow.
- AI-assisted CSV/JSON mapping with batched row review and an atomic apply (`lib/data-intake`, `asset.se-live.ai-assisted-csv-json-customer-table-intake`). Observed live: heuristic auto-map was missing, AI suggestion mapped four columns correctly in about 4.2 s.
- Idempotent AI task router with a durable run ledger and budgets (`lib/ai`, `lib/usage`).
- Encrypted connector vault, OAuth and adapter registry (`lib/integrations`, 19 adapters: Gmail, Calendar, Drive, Microsoft 365, HubSpot, Salesforce, Pipedrive, Slack, Teams, Zendesk, Intercom, WhatsApp Cloud, Telegram, signed webhook and more). Check/read only, no tenant ever connected one.
- Durable outbound delivery with accepted/rejected/uncertain states and no auto-resend of uncertain outcomes (`lib/delivery`).
- Agent version/release/rollback gating and public deployment boundary with frozen snapshot, origins and session caps (`lib/deployments`, `lib/platform`).
- Auth lifecycle and team roles (owner/operator/viewer), WhatsApp and Telegram channel workers.
- Container Apps Bicep, readiness and package checks (`infrastructure/azure`, never applied).
- Known fix-before-reuse defects: bypassable offering-approval gate, customer CSV leaking into company knowledge, duplicated AI-disclosure logic.

## 7. Gaps the blueprint must fill (nothing existing covers them)

- Tenancy, auth, roles, billing/wallet, spend caps and concurrency limits (the lab has a shared passcode).
- Contact objects with DND status, consent, attempt history and timezone (must-be B in the walkthrough synthesis); campaign object with schedule, retries, pacing and a dialler queue.
- Production telephony: inbound and outbound at concurrency, DLT/TRAI compliance, caller-ID, answering-machine detection, transfer, SIP trunking.
- LLM-native, chat-driven setup that builds agents, imports data and launches campaigns; the owner wants the client to "just talk".
- Omni-channel data ingestion and what is useful in it; WhatsApp/SMS/email as channels (Relay has partial adapters, none proven).
- Analytics and call review: transcript plus stereo audio exist per call in the lab; per-call AI analysis, campaign dashboards and outcome extraction do not exist outside Relay's text-only result extractor.
- Memory, personalisation and self-learning: only a preference-note stub in the lab; the graph rejects cross-tenant pooling (`rejected.2026-10-17.cross-tenant-pooling`) and daily-checked K=2 A/B dashboards as "self-learning" (`rejected.2026-10-17.k2-dashboards`), so learning must be per-tenant and statistically honest.
- Languages beyond Hindi/Hinglish, and Indian-language lexicons for turn-taking, goodbye detection and ledger cues.
- Observability and reliability: per-turn trace exists as a 600-entry in-memory trace per call; no incident ledger, no failover policy.
- Safety by predicate: the lab's safety rules live in the prompt; the inherited rule says predicates on output bytes.

## 8. Recommended use, in priority order

1. Treat `voicelab/server/{providers,catalog,calls,persona_v2,phone,audio}.py` as the **specification and reference implementation** of the call engine. Port, don't rewrite from scratch, but split the 807-line `calls.py` along its seams (Call base, Reply, CascadeCall, S2S bridges) when porting.
2. Keep the evidence discipline as product features: combination identity as a full run manifest, invalid-with-reason calls, per-call metered INR cost, blind/rated bake-offs.
3. Generalise brief v2 and the ledger from four hard-coded scenarios to per-agent configuration with deterministic runtime; add output predicates for disclosure, crisis lines and facts.
4. Rebuild the product shell, data model and UI fresh; take Relay's mechanisms as design references, borrow `/prototype`'s warmth, drop the rest.
5. Re-run the unknowns that decide the default stack (Vertex return, round-2 human ratings, handset reply gap, turn-taking against the 5% / 1.2 s target) before locking the default.
