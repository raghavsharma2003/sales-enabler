# Vapi product map — verified desk research

**Research date:** 2026-09-22 (Asia/Kolkata). **Method:** current public first-party documentation and product-release pages, read without an account, API key, phone number, purchase, or call. This is capability evidence, not a claim that the feature is enabled on every account, reliable in our target workflow, or present in an uninspected live UI.

## Evidence labels

* **Documented** — a current Vapi page states the mechanism or gives a configuration/API example.
* **Documented dashboard surface** — a current Vapi guide tells the operator to use a named dashboard location or depicts it. It is not independent hands-on observation.
* **Vendor metric / marketing** — first-party measurement or positioning; use for comparison, not our promise.
* **Unverified hands-on** — intentionally not performed in this research. Absence from this report means only that it was not established from the reviewed public pages.

## The operating path Vapi documents

| Stage | Documented screen / object / operator action | What this means for a company-operations product |
|---|---|---|
| Onboard and choose a starting point | **Assistants → Create Assistant** opens a blank assistant; the adjacent menu offers templates. A default new assistant uses the **Balanced** preset. [Assistant quickstart](https://docs.vapi.ai/assistants/quickstart) | Start with a guided objective and a safe template, but keep our own organization, customer-data and consent setup before any assistant can talk. |
| Create and publish an assistant | In the assistant editor, fill **First Message** and **System Prompt**; select **Publish → Quick Publish**. Publishing creates an assistant version. The documented dashboard test is **Talk**, a browser/microphone call. [Assistant quickstart](https://docs.vapi.ai/assistants/quickstart) | A useful product pattern: draft/version/publish/test are separate states. The current mock has conversation context and a browser adapter boundary, but no explicit agent version, publish history, or isolated pre-production test state. |
| Select speech, reasoning and voice | Vapi composes an assistant from an STT transcriber, LLM and TTS voice. **Model Intelligence** offers Balanced, High Intelligence, Ultra Fast and Cost Saver presets, then individual provider/model overrides; the model picker is the live source of selectable choices. [Model Intelligence](https://docs.vapi.ai/assistants/model-intelligence/overview) | Copy the three-component configuration and show cost/latency trade-offs, but retain our provider-neutral adapter. Vapi's displayed totals should not be shown as a live-SLA estimate: they omit endpointing and transport and its cost is estimated. |
| Tune turn-taking | **Assistant → Advanced → Start Speaking Plan / Stop Speaking Plan** exposes wait, smart or transcript endpointing, interruption thresholds, acknowledgement phrases and recovery backoff; changes require Publish. The pipeline is VAD → transcription → endpoint decision → LLM → TTS. [Voice pipeline](https://docs.vapi.ai/customization/voice-pipeline-configuration) | This is a stronger operational control surface than a generic “natural voice” setting. Make timing stages, interruption disposition, language and configuration version visible per session. |
| Add knowledge and actions | **Tools** can be reused across assistants, are versioned, and may pin a version. Documented types include server Function/API Request, transfer, handoff, voicemail, knowledge Query, MCP and integrations. Static parameters are server-controlled; the docs describe rejection plans and argument encryption. [Tools](https://docs.vapi.ai/tools) Knowledge files are associated through an assistant’s **Files / Knowledge Base** section; publishing creates the default query tool. [Knowledge bases](https://docs.vapi.ai/knowledge-base) | Adopt versioned capabilities and a separation between model-facing and server-controlled inputs. Do not treat file upload/retrieval as a company brain: preserve source, scope, expiry, correction and per-record authorization in our system. |
| Choose client versus server tool execution | A Web SDK client-side tool has no server URL, emits `tool-calls` to the frontend, can create UI effects and can inject a message; it **cannot return a result to the model**. Use a server tool where the result changes further reasoning. [Client-side tools](https://docs.vapi.ai/tools/client-side-websdk) | Fit for “open customer card” or highlight a consent control. Customer reads/writes, appointment booking and integrations belong behind our server authorization/idempotency gateway. |
| Test before live use | Text-model **Evals** check a next decision, response and tool arguments with exact/regex/AI judges; Vapi explicitly says they do **not** test STT, audio quality or turn-taking. [Evals](https://docs.vapi.ai/observability/evals-quickstart) **Simulations** run reusable suites against an assistant or Squad in chat or synthetic voice mode, with iterations, transcript/recording and criteria; unmocked tools run for real. [Simulations](https://docs.vapi.ai/observability/simulations-quickstart) | Adopt distinct decision, synthetic voice and controlled-real-call test layers. Require sandbox/mocks for action tools. No simulation pass should be presented as a verified booking or customer outcome. |
| Connect a number and test a real route | **Phone Numbers → Create Phone Number** can create one free US inbound-only Vapi number, or import a provider number. **Inbound Settings** assigns an Assistant or Squad. The number’s **Test** panel places or schedules a one-number call. Free Vapi numbers cannot make outbound/international calls. [Phone calling](https://docs.vapi.ai/phone-calling) | This is a later channel for us. Do not reproduce Vapi’s phone-first entry point ahead of browser calls. A provider import/telephony setup needs its own permissions, consent and routing controls. |
| Design multi-specialist journeys | **Squads** are a list of specialist assistants; the first starts and handoff tools decide destinations. Their handoffs can target assistants or specialist destinations and preserve conversation context across the transition. [Squads](https://docs.vapi.ai/squads) | Adopt focused skills and explicit handoff contracts only when one assistant no longer has a crisp objective. Keep the event history and human handoff independent of model-extracted variables. |
| Launch outbound work | **Campaigns → Create campaign** selects an outbound-capable number, assistant, max concurrency, optional webhook/pre-dial eligibility check, and CSV/manual contacts with dynamic variables. It supports now/later and a calling window up to seven days ahead. Post-create campaigns are read-only; operators monitor and may cancel or duplicate. [Campaign quickstart](https://docs.vapi.ai/outbound-campaigns/quickstart) | Strong lifecycle inspiration: preflight → review → launch → immutable run → contacts/results. Our mock has campaign strategy and journeys, but lacks a reviewable execution object with suppression/consent evidence, capacity, dialing windows, outcome taxonomy and cancellation semantics. |
| Inspect calls and debug | **Logs → Calls → call detail** exposes enabled recordings, transcript, messages, artifacts and detailed `logUrl`; artifacts can be stored in Vapi cloud or customer S3/GCS. Per-call artifact settings can override assistant settings. Phone PCAP is available when enabled. [Call artifacts](https://docs.vapi.ai/assistants/call-recording) | Add a trace timeline: audio/turn events, chosen prompt+tool versions, retrieval sources, action request/result, takeover and final disposition. Use retention/deletion controls before making recordings a default. |
| Evaluate operations and follow up | **Scorecards** score post-call structured outputs, normally seconds after completion, and are retrievable on the call artifact. Vapi warns that AI-generated structured outputs can be wrong. [Scorecards](https://docs.vapi.ai/observability/scorecard-quickstart) **Monitoring** periodically queries call data, thresholds it, opens issues, and sends email/Slack/webhook notifications. [Monitoring](https://docs.vapi.ai/observability/monitoring-quickstart) | Use scores as triage, never as the canonical customer truth. Pair quality alerts with analyst review, exact evidence and a regression test/action loop. |

## Voice behaviour, costs and scale — actual documented bounds

* **Interruption and backchannels (documented):** `numWords: 0` uses VAD and Vapi describes interruption at roughly 50–100 ms; transcription-based detection is described as 200–500 ms. `acknowledgementPhrases` can suppress an interruption, `interruptionPhrases` can clear it, and `backoffSeconds` blocks assistant audio after an interruption. These are configuration mechanics, not accuracy results. [Voice pipeline](https://docs.vapi.ai/customization/voice-pipeline-configuration)
* **Endpointing/language (documented):** the guide calls its LiveKit smart endpointing English-only. Transcription-rule endpointing is presented as language-independent. This does not establish Hindi-English code-switch accuracy. [Voice pipeline](https://docs.vapi.ai/customization/voice-pipeline-configuration)
* **Concurrency (documented, not a public numerical limit):** campaigns require a max concurrency within the organization’s available capacity. No general public numeric cap was established from the reviewed primary pages. [Campaign quickstart](https://docs.vapi.ai/outbound-campaigns/quickstart)
* **Price/cost (vendor metric, not a price quote):** component panels show a calculated estimated per-minute cost. Its inputs include audio minutes, prompt/tool definitions, caching and characters; estimates exclude growing conversation history and can differ by contract. Validate complete marginal cost and credits in the account/contract before modeling a campaign. [Metric methodology](https://docs.vapi.ai/assistants/model-intelligence/metrics-methodology)
* **Billing, teams and permissions:** public reviewed docs identify Billing & Payment as the place to inspect plan/retention, provider-key connections under Integrations, and organization capacity settings. They did not establish a full public team/RBAC/invite/audit-log workflow or a public plan-price/concurrency table. That is a factual gap to verify in an account or sales/security review, not evidence of absence. [Call artifacts](https://docs.vapi.ai/assistants/call-recording), [provider keys](https://docs.vapi.ai/customization/provider-keys)

## Current product-direction implications

**Adopt:** assistant draft/version/publish/test; a visible three-component voice configuration; separate decision evals from voice simulations; immutable campaign runs; context-aware specialist handoffs; and traceable, post-call QA.

**Adapt:** use client tools only for presentation controls and submit all customer data/actions to our policy gateway; replace Vapi-style file-only knowledge with sourced relational memory; make speech timing an observable implementation detail rather than a warmth claim; and put consent/suppression, human review and action idempotency ahead of campaign launch.

**Avoid:** a visual node-and-edge workflow builder as the primary future model. Vapi’s current migration documentation says legacy Workflows were discouraged, were to stop on 2026-08-18, and positions Squads/handoffs as their replacement. The research date is after that date, but no hands-on confirmation of an account’s migration state was made. [Workflows migration](https://docs.vapi.ai/workflows/legacy-migration)

The present Relay sample prototype correctly keeps phone later, uses source-aware memory and makes actions proposals. Its factual product gaps relative to the documented Vapi operating model are not “missing features” to blindly copy: they are the explicit release/version path; assistant configuration plus voice timing view; tool contract/version/result trace; browser test/simulation/eval distinction; campaign run lifecycle/limits; call-artifact/debugging record; and quality-monitoring-to-team-improvement loop. It should not add phone dialling, provider billing or claims of natural interruption performance until a selected provider and real evaluation evidence exist.
