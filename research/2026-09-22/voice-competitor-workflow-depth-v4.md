# Voice competitor workflow depth v4

**Research date:** 2026-09-22 (Asia/Kolkata). **Scope:** bounded review of current public first-party documentation, product pricing and API/reference pages for Vapi, ElevenLabs Agents, Bolna and Retell. The earlier reports in this folder cover the broad product maps; this report records the newer workflow, scale, pricing and operating details that change the next product decisions. No account, credential, phone number, payment method, upload or live call was used.

## Evidence boundary

- **Documented:** the vendor’s current public docs specify the mechanism, screen, API field or limit.
- **Vendor claim:** the vendor presents a performance, speed, quality or setup claim; it was not independently measured here.
- **Inference:** a product implication derived from the documented behavior.
- **Unverified logged-in UX:** a page tells an operator to use a dashboard surface, but this review did not enter the dashboard. No authenticated hands-on observation is claimed.
- **Not established:** the reviewed public sources did not establish the capability. This is not proof that the capability does not exist.

## Vapi

### Actual documented path: build → test → launch → inspect

1. **Onboard/build (documented dashboard surface, unverified logged-in UX):** `Assistants → Create Assistant` offers blank or template creation. The assistant editor accepts a first message and system prompt; dashboard changes are published as a version, while SDK updates take effect immediately in the current docs. `Talk to Assistant` is the browser/microphone test, so a phone number is not required for first rehearsal. [Assistant quickstart](https://docs.vapi.ai/assistants/quickstart) · [Inbound support example](https://docs.vapi.ai/assistants/examples/inbound-support)
2. **Knowledge/configuration (documented):** the assistant combines transcriber, LLM and voice; model-intelligence presets expose Balanced, High Intelligence, Ultra Fast and Cost Saver before individual provider choices. Files are attached through a knowledge base and queried by a generated tool. Tools are reusable, versioned and can pin a version; client-side web tools can affect UI but cannot return a model result. [Model intelligence](https://docs.vapi.ai/assistants/model-intelligence/overview) · [Tools](https://docs.vapi.ai/tools) · [Knowledge bases](https://docs.vapi.ai/knowledge-base)
3. **Workflow/actions (documented):** Squads are specialist assistants with explicit handoff tools and context preservation. The docs’ workflow migration guidance positions Squads/handoffs as the replacement for legacy Workflows; this is a product-direction signal, not evidence of a currently inspected account migration. [Squads](https://docs.vapi.ai/squads) · [Workflow migration](https://docs.vapi.ai/workflows/legacy-migration)
4. **Tests/evals (documented):** Evals run mock text/model decisions and tool argument checks; Vapi explicitly excludes STT, audio and turn-taking. Simulations run reusable text or synthetic-voice conversations, can configure the AI tester’s model/transcriber/voice, and can mock tools, but unmocked tools execute for real. Scorecards grade post-call structured outputs; monitoring queries retained historical calls and can notify by email, Slack or webhook. [Evals](https://docs.vapi.ai/observability/evals-quickstart) · [Simulation AI tester](https://docs.vapi.ai/observability/simulations-configure-ai-tester) · [Scorecards](https://docs.vapi.ai/observability/scorecard-quickstart) · [Monitoring](https://docs.vapi.ai/observability/monitoring-quickstart)

### Bulk, handoff and measurement depth

- **Campaign object (documented):** a campaign can contain up to **10,000 contacts**; `maxConcurrency` is API-documented as **1–500**, bounded by organization capacity. Each CSV row can carry dynamic variables. A current run has pending/dispatched/completed/failed/skipped/pre-dial-failed contact states and per-row call ID, end reason, duration and cost. [Campaign overview](https://docs.vapi.ai/outbound-campaigns/overview) · [Create campaign API](https://docs.vapi.ai/api-reference/campaigns/campaign-controller-create)
- **Preflight and lifecycle (documented):** the optional blocking `campaign.predial` webhook can re-check current consent, suppression, account state and timezone immediately before dialing. Dashboard scheduling is up to seven days ahead. Creating starts/schedules immediately; there is **no saved draft**, configuration becomes read-only, and reruns require duplicating the campaign. Cancellation is the only update operation; archive is soft deletion. [Scheduling/lifecycle](https://docs.vapi.ai/outbound-campaigns/scheduling-and-lifecycle)
- **Handoff (documented/inference):** Squad handoffs preserve conversation context; human/number transfer is a tool. The useful product contract is a named destination plus a traceable transfer event, not a hidden persona change. Whether a human receives a business-safe context brief is not established by these pages.
- **Analytics limitation (documented):** scorecards depend on AI-generated structured outputs that Vapi warns can be wrong. Monitors require retained call data and do not evaluate organizations using Zero Data Retention. This is a concrete reason to display evidence and retention state beside any quality score. [Scorecard](https://docs.vapi.ai/observability/scorecard-quickstart) · [Monitoring](https://docs.vapi.ai/observability/monitoring-quickstart)

### Current price/limits and missing extras

- **Documented current pricing shape:** Usage-only billing is per-minute hosting plus model, voice, transcriber and telephony charges. Usage-only has documentation/Discord support and no response or uptime SLA. Optional Core/Pro/Premier packages add support, service commitments and higher limits; current docs list **4/10/30/custom concurrent call lines**, raw retention **14/30/180/custom days**, and basic/custom RBAC depending on package. Core is fixed monthly; Pro scales with hosting spend; Premier is custom. [Pricing and Success Packages](https://docs.vapi.ai/billing/pricing-and-success-packages)
- **Missing/unclear extras:** public pages did not establish India carrier eligibility, regional processing, a consent registry, per-contact suppression history, full audit-log semantics or a public all-in INR estimate. Cost is an estimate and provider keys can move component charges directly to the provider. [Provider keys](https://docs.vapi.ai/customization/provider-keys)
- **Operational limitation:** no campaign draft means an operator cannot save a partially reviewed launch in the Vapi object itself. Pre-dial checks are powerful but require an external source of truth and webhook reliability.

### UX decisions for our product

Reuse a clear `draft → test → preflight → launch → immutable run → duplicate` path, but add an explicit draft and review boundary. Show each contact’s inclusion/consent/suppression reason, effective capacity, agent/tool/knowledge versions, and a cancellation/partial-run ledger. Keep a provider-independent trace because Vapi’s text Evals, synthetic simulations and real calls answer different questions.

## ElevenLabs Agents

### Actual documented path: configure an agent bundle → test → branch → deploy → analyze

1. **Onboard/configure (documented dashboard surface, unverified logged-in UX):** the Agents product exposes agents, a visual workflow builder, Integrate and Monitor/Testing areas. Configuration spans system prompt/personality, LLM and cascade, voice/TTS, first message, language, turn-taking and guardrails. Knowledge can be full-context for small material or RAG for larger sources; the guide gives about **250 ms added RAG response latency** as a vendor-documented approximation. [Agents overview](https://elevenlabs.io/docs/eleven-agents/overview) · [Knowledge base](https://elevenlabs.io/docs/eleven-agents/customization/knowledge-base)
2. **Tools/workflow (documented):** client, webhook, sandboxed code, MCP and system tools are available. Workflows compose subagents, dispatch, AI-agent transfer, phone transfer and end nodes. Transfer to a child agent carries the current language when supported; prompt, first message, LLM, workflow, voice, tools and knowledge are otherwise child-owned and must be configured consistently. [Tools](https://elevenlabs.io/docs/eleven-agents/customization/tools) · [Agent transfer](https://elevenlabs.io/docs/eleven-agents/customization/tools/system-tools/agent-transfer)
3. **Testing (documented):** Simulation tests grade multi-turn outcomes, Next Reply tests a response against criteria, and Tool Call tests expected tool/arguments by exact match, regex or LLM evaluation. Tests can be created from existing calls, run individually, in a batch or with Run All Tests. Dynamic variables can mirror production values. [Agent testing](https://elevenlabs.io/docs/eleven-agents/customization/agent-testing)
4. **Release (documented):** enabling versioning creates immutable configuration snapshots covering conversation configuration, platform settings such as evaluation/data collection/webhooks/safety, and the full workflow. Drafts are per-user/per-branch; branches can merge/rebase; traffic splits must total exactly 100% and deterministically route by conversation ID. Versioning cannot be disabled after enablement. [Agent versioning](https://elevenlabs.io/docs/eleven-agents/operate/versioning) · [Experiments](https://elevenlabs.io/docs/eleven-agents/operate/experiments)

### Bulk, handoff and measurement depth

- **Bulk campaign status:** the reviewed public Agents docs specify API/web/phone deployment and dynamic variables, but no current first-party page established a native CSV campaign/batch control plane comparable to Vapi, Bolna or Retell. This is **not established**, not an absence claim. For our product, do not make “agent API call” look like a governed campaign run.
- **Post-call loop (documented):** success evaluation returns success/failure/unknown with rationale; data collection extracts structured fields; analytics and Spotlight aggregate outcomes, sentiment and topics. Post-call transcription webhooks include transcript, analysis, metadata, dynamic variables and the active `version_id`; HMAC authentication is documented. Repeated webhook failures can auto-disable delivery after 10 consecutive failures when there has been no successful delivery for more than seven days (or never). [Conversation analysis](https://elevenlabs.io/docs/eleven-agents/customization/agent-analysis) · [Post-call webhooks](https://elevenlabs.io/docs/eleven-agents/workflows/post-call-webhooks)
- **Handoff (documented/inference):** agent transfer and external number transfer are available. Because child agents do not inherit most parent configuration, a handoff contract must include language, disclosure, tools, knowledge and escalation expectations. Do not assume “transfer” means a human received all relevant customer context.

### Current price/limits and missing extras

- **Documented current Agents pricing:** Free includes 15 call minutes/4 concurrent calls; Starter 75/6 at **$6 per month**; Creator 275/10 at **$22** (first month $11); Pro 1,238/20 at **$99**; Scale 3,738/30 at **$299**; Business 12,375/40 at **$990**. Additional calls are **$0.08/minute**; burst pricing is **$0.16/minute** and can reach up to 3× normal concurrency. Text messages are **$0.003 each**. LLM charges are displayed in the UI and deducted from credits; telephony is usage-based/at cost. [ElevenAgents pricing](https://elevenlabs.io/pricing/agents)
- **Missing/unclear extras:** no public campaign suppression/retry/window object was established in the reviewed docs. The model and telephony bill of materials needs an estimator or measured pilot; included-minute figures are not a complete INR outcome cost. Public language configuration does not prove native Indian accent, code-switch or entity accuracy.
- **Operational limitations:** system/workflow tools cannot all be mocked; RAG adds latency; versioning is irreversible once enabled; and child-agent transfer can silently diverge in prompt, voice, tools and knowledge unless the builder checks the bundle.

### UX decisions for our product

Adopt version branches and deterministic traffic splits only with an explicit test baseline, release gate and rollback view. Store the originating agent version on every conversation and webhook. Make `unknown` analysis a review queue state. Add a campaign layer above agent invocation, with consent, suppression, schedule and capacity evidence.

## Bolna

### Actual documented path: Agent Studio/graph → India voice stack → batch/workflow → extraction

1. **Onboard (documented/vendor claim, dashboard unverified):** Agent Studio claims a **5–8 minute** path from a brief to a call-ready agent and no prompt writing: identity/goal, conversation, closing, optional business material and generated editable configuration. The current docs also expose Conversation, Graph and IVR agent types, plus graph editor validation/version history. [Agent Studio](https://www.bolna.ai/docs/agent-setup/studio) · [Agent types](https://www.bolna.ai/docs/concepts/agent-types)
2. **Knowledge/voice/prompt (documented):** PDFs/URLs form RAG knowledge bases; multilingual knowledge mode and per-language prompts are available. Graph agents support global and per-node knowledge/tools. The graph editor validates before save, blocks duplicate IDs/missing starts/unreachable tools/malformed transitions and presents non-blocking warnings for empty prompts or unreachable nodes. [Knowledge base](https://www.bolna.ai/docs/knowledge-base) · [Graph validation](https://www.bolna.ai/docs/graph-agent/validation)
3. **Tools/workflows (documented):** tools include calendar booking, transfer and generic external API. The workflow feature is labeled **BETA** in the docs and combines agent calls, extraction, API, time/wait, retry, WhatsApp and end nodes; workflow campaigns run published workflows over thousands of contacts. Graph-specific mechanics include router/static nodes, deterministic silence replay, event injection from REST, version history and node-scoped RAG/tools. These are concrete control-plane features, but the beta label is a launch risk. [Docs index](https://www.bolna.ai/docs/llms.txt) · [Graph tools/RAG](https://www.bolna.ai/docs/graph-agent/tools-and-rag)
4. **Testing/QA (documented):** graph testing supports text chat simulation or a real outbound call; extraction templates can be tested against sample or real transcripts. The reviewed docs do not establish an automated multi-version regression suite with pass/fail release enforcement. That gap should be treated as a product decision, not filled by claiming Studio generation is QA.

### Bulk, handoff and measurement depth

- **Batches (documented):** CSV requires E.164 `contact_number`; other columns are passed through as variables without validation. Dashboard supports Run Now/Schedule, managed or own number, stop/download/delete, webhook and auto-retry. Retry can target no answer, busy, failed, error or voicemail, up to three attempts with increasing intervals. Webhooks deliver status, transcript, extracted data and cost; API execution data includes duration, total cost and STT/LLM/TTS usage breakdown. [Batch calling](https://www.bolna.ai/docs/outbound/batch-calling)
- **Capacity (documented):** Enterprise organizations can allocate a guaranteed `min_concurrency` and optional `max_concurrency` to each account/sub-account; excess queues rather than drops, and provider queues are isolated. This is useful for protecting support capacity from outbound bursts. [Concurrency management](https://www.bolna.ai/docs/enterprise/concurrency-management)
- **Handoff/analytics (documented):** transfer tools and extraction categories such as Agent Handover produce post-call structured signals. The Extractions tab can send execution data in real time, summarize calls and test extraction templates before production. [Extractions/analytics](https://www.bolna.ai/docs/agent-setup/analytics-tab)

### Current price/limits and missing extras

- **Two current public price representations need reconciliation:** the pricing website shows usage credits from **$10–$5,000**, a volume display of **$0.06/min (₹5.52)** with lower rates at higher volume, and Pilot options including **$500 for 12,000 minutes** or **$300 for 6,500 minutes**, billed in 30-second pulses, up to 25 concurrent calls and one month of guided support. The docs describe the older component model: STT+LLM+TTS + carrier + a flat **$0.02/minute platform fee**, with preferred models bundled into a workspace flat rate and BYOK removing provider component charges. [Pricing website](https://www.bolna.ai/pricing) · [Call pricing docs](https://www.bolna.ai/docs/pricing/call-pricing)
- **Missing/unclear extras:** treat the website and docs as current vendor surfaces with a reconciliation question, not as one combined quote. Validate exact preferred-model list, carrier pulse rules, retry billing, concurrency tier and India processing contract before TCO. No public independently measured WER, end-to-end latency or business outcome evidence was established.
- **Operational limitation:** Workflows are marked beta; custom variables are passed through as-is in batches, so schema validation, consent/DNC and PII minimization must be imposed by our platform.

### UX decisions for our product

Borrow pre-save validation and click-to-error navigation for workflows, plus explicit static-vs-LLM node semantics. Keep Company Brain sources and agent instructions separate, attach evidence at node/phase scope, and model guaranteed inbound capacity separately from campaign capacity. Treat generation, extraction and vendor claims as accelerators—not release evidence.

## Retell

### Actual documented path: template/Conductor → test layers → phone/web deploy → live supervision

1. **Onboard (documented dashboard surface, unverified logged-in UX):** new accounts start with **$10 trial credits** and no payment method; create an agent from scratch, template, single prompt, conversation flow or Conductor plain-English generation. Draft agents can be tested with a free browser call before a phone number. Retell-managed phone numbers are US/Canada only; other countries use custom telephony. [Quick start](https://docs.retellai.com/get-started/quick-start)
2. **Knowledge (documented):** sources include URLs, many document formats, text, Google Drive, OneDrive and Notion. URL/connected sources can auto-refresh every 24 hours; URL paths can auto-crawl. Limits are 500 URLs, 50 text snippets, 25 files/50 MB each (spreadsheets 1,000 rows/50 columns). Retrieval condenses the recent transcript without the prompt, supports 1–10 chunks (default 3) and a similarity threshold (default 0.60), and can be configured at agent, conversation-node or subagent-node level. Retrieved chunks are visible through a Knowledge Base Retrieval link in call history. [Knowledge base](https://docs.retellai.com/build/knowledge-base)
3. **Prompt/tools/workflow (documented):** single/multi-prompt agents and conversation-flow agents support function, integration, code, MCP, transfer, DTMF, SMS, logic-split, global, end and agent-transfer nodes. Reusable subflows, Flex Mode and finetune examples provide structured refinement. Transfer supports cold, warm and agentic warm modes. [Retell docs index](https://docs.retellai.com/llms.txt)
4. **Testing/release (documented):** LLM Playground inspects/replays turns and tool calls; simulation tests grade saved scenarios; batch simulation catches regressions; web tests validate real audio/latency/interruption without a number; phone tests validate carrier audio, DTMF, transfers and voicemail. Custom-LLM and speech-to-speech agents are audio-only, so simulation/batch testing is unavailable for them. Test pricing is separate: text tests are per message and web/phone tests use production per-minute rates. [Testing overview](https://docs.retellai.com/test/test-overview) · [Testing pricing](https://docs.retellai.com/test/testing-pricing)

### Bulk, handoff and measurement depth

- **Batch object (documented):** create/schedule/save a draft in the Batch Call tab, choose a bound `From Number`, upload CSV, inject arbitrary dynamic variables, and optionally override agent ID/version, metadata and SIP headers per row. The operator can set reserved concurrency for inbound calls, then Send Now or schedule. Batch docs do not establish a public maximum row count. [Batch calls](https://docs.retellai.com/deploy/make-batch-call)
- **Continuity (documented/inference):** Contacts are keyed by phone number, receive post-call extracted fields and feed fields back as dynamic variables on later calls. CRM sync and DNC fields are documented. Web calls/chats have no phone number and therefore do not create contacts, a material boundary for a browser-first relationship model. [Contacts](https://docs.retellai.com/features/contacts)
- **Live handoff (documented):** Live Monitoring lists active calls, streams transcript, allows silent listen, takeover or end-call from dashboard/Web SDK. Takeover requires Admin/Developer or a custom call-management role; PII scrubbing occurs only after the call, so raw-data permission is required for live monitoring. [Live monitoring](https://docs.retellai.com/features/live-monitoring)
- **Analytics/QA (documented):** custom dashboards chart call/chat volume, success, latency, cost, concurrency and custom post-call extraction fields; filters/breakdowns compare agents or versions. Post-call extraction, webhooks, alerts and AI QA add structured outcomes and issue trends. [Analytics](https://docs.retellai.com/features/analytics-dashboard) · [AI QA](https://docs.retellai.com/ai-qa/overview)

### Current price/limits and missing extras

- **Documented current pricing:** pay-as-you-go voice agents show **$0.07–$0.31/minute**, $10 free credit and 20 concurrent calls. Detailed pricing decomposes Retell voice infrastructure ($0.055/min), platform voices ($0.015/min), LLM by model, telephony (for example $0.015/min for a shown country), and add-ons such as knowledge base **+$0.005/min**, Batch Call **+$0.005/dial**, branded call **+$0.10/outbound call**, advanced denoising/safety **+$0.005/min**, PII removal **+$0.01/min**, and AI QA **$0.10/min after the first 100 minutes**. Extra concurrency is $8/concurrency/month; phone numbers are $2/month. [Retell pricing](https://www.retellai.com/pricing)
- **Billing boundaries (documented):** calls are tracked to the nearest second; silence/hold is billable while STT listens; failed-to-connect calls are not billed; after transfer, the AI fee stops while telephony continues. These rules materially change cost-per-outcome modeling. [Retell pricing FAQ](https://www.retellai.com/pricing)
- **Limitations:** Retell-managed numbers are US/Canada only; India needs imported/SIP telephony and its carrier economics. Live PII scrubbing is unavailable mid-call. The 20-call default and reserved inbound capacity need explicit preflight for outbound work. Public docs did not establish local Indian data residency or DLT/KYC behavior for an Indian carrier.

### UX decisions for our product

Adopt Retell’s strongest operator pattern: a contact timeline that feeds future calls, a saved batch draft with reserved inbound capacity, live transcript/takeover, and dashboards whose custom fields can be business outcomes. Make phone identity one optional key, not the only relationship key, so browser conversations still belong to the same customer record. Show live-monitoring permissions and raw/PII state before an operator listens or takes over.

## What this means for the current app

The current prototype diagnosis already identifies that the app is a scripted campaign walkthrough. The four products provide enough additional evidence to make the next five gaps concrete:

1. **Versioned agent and Test Lab:** create an editable agent bundle (prompt, language/voice, knowledge, tools, handoff and runtime), named scenario cases, mockable actions, pass/fail results and a release gate. Link every simulated or live conversation to the exact bundle version. This combines ElevenLabs branches/tests, Vapi’s Evals/simulations and Retell’s layered testing.
2. **Company Brain ingestion and retrieval evidence:** model source, owner, permissions, freshness/index status, authoritative field, conflict and scope; show the exact retrieved claim at the turn. Retell’s source refresh/limits and node-level retrieval make this reviewable, while Vapi/Bolna file KBs demonstrate why file upload alone is not a company brain.
3. **Governed campaign control plane:** save a draft, show editable cohort rows and inclusion/suppression reasons, re-check eligibility at dispatch, expose time window/retry/stop rules, calculate capacity and cost, require preflight, and create immutable per-person results. Vapi’s no-draft fixed campaigns, Bolna’s retry ladder and Retell’s reserved-inbound batch are concrete reference points.
4. **Conversation trace, action ledger and human rescue:** expose context sources, turn/timing events, tool arguments/results, proposed memory, disclosure, transfer destination, permitted handoff brief, takeover and final disposition. Retell’s live takeover and Vapi’s call artifacts show the operational shape; the current scripted agent cannot inspect any of it.
5. **Outcome/quality loop:** custom extraction fields, reviewer disagreement, alerts, cohort/version/language breakdowns, regression-case creation and an outcome ledger connecting conversations to requested versus confirmed business results. Retell custom dashboards, Bolna extractions, ElevenLabs post-call webhooks and Vapi scorecards/monitoring show the components; none removes the need for our own source-of-truth and consent semantics.

These are product operating objects, not provider-specific copies. Phone numbers, carrier setup and real sound metrics remain later, explicitly labelled integration work. No public documentation reviewed here proves Indian-language accuracy, emotional understanding, relationship quality or business ROI; those require representative India audio/evaluation data and a controlled pilot.
