# Accessibility check, WCAG 2.1 AA (2026-10-24)

**What ran.**
- **axe-core 4.10.2** (npm dev dependency), WCAG 2.0 and 2.1 A and AA rules.
- **24 screen states** of the seeded workspace, each at desktop (1440 px) and phone (390 px). Three are in an opened state: the
  test panel, the import's row verdicts and the approval sheet.
  - The **gate** runs light mode: 48 states.
  - The **one-off table run** added dark mode: 96 states.
- Driver: `product/web/e2e/a11y.mjs`. Run it with `node product/web/e2e/a11y.mjs <base>` for the full JSON.
- **Gate**, in `product/web/e2e/flows.test.mjs`: *Accessibility: no serious or critical axe violation on any main screen,
  desktop and phone*. It fails on any new serious or critical violation.

**Result.**

| Run | Screen states | Critical | Serious | Moderate | Minor |
|---|---|---|---|---|---|
| Before (d3b9f97 build), light | 48 | 0 | 24 (1 rule) | 0 | 0 |
| After, light | 48 | 0 | 0 | 0 | 0 |
| After, dark | 48 | 0 | 0 | 0 | 0 |

**The one violation before.** It was `color-contrast` on every desktop screen: the sidebar's "Asha Rao · owner" line. It was
dimmed with an inline `opacity: 0.8`, so neither axe nor a person's contrast tool could see its true pair. It is now the
`--nav-ink-dim` token on `--forest-2`, which measures 5.09:1 in light and 6.95:1 in dark. That pair is added to the
token-contrast unit test, so the 5:1 rule still holds for every token pair. The role also reads "Owner", not "owner".

## Beyond the automated rules

| Check | Result | How |
|---|---|---|
| Keyboard-only completion of the main flows | **Passes.** Create an agent from a template, start a browser test call and hang up, import a CSV, publish (approve by pressing twice), and set the launch spend cap. Every control was reached with Tab and activated with Enter. | Flow *Keyboard only: …*. `tabTo` presses Tab until the control has focus, so tab order is exercised, not skipped. It passed on the old build too: these flows were already keyboard-complete. |
| Bypass blocks (2.4.1) | **Fixed.** There was no skip link. "Skip to main content" is now the first Tab stop and moves focus to `<main>`. | Flow *Keyboard: the first Tab stop skips the navigation to the page*. It failed before and passes now. |
| Focus in dialogs | **Fixed (latent).** The dialog's focus effect depended on `onClose`, and most callers pass a new function on every render. Any re-render inside a sheet threw focus back to its first control. It now runs once per opening. Focus is still trapped, Escape still closes, and focus still returns to the opener. | The keyboard flow types into the cap field and asserts focus stays there. No current flow re-rendered the parent mid-typing, so this did not fail before. It is a guard. |
| Focus visible (2.4.7) | **Holds.** `:focus-visible` draws a 3 px `--focus` outline on every control. | `app.css:23`; seen in the keyboard run. |
| Reduced motion (2.3.3) | **Fixed for scripts.** CSS already removed animations and transitions under `prefers-reduced-motion`. The JS scrolls (tab arrows, the live call coming into view, transcript seek) were still smooth. They now use `scrollMotion()`, which honours the setting. | `ui.tsx` `scrollMotion`. |
| Reflow at 320 px (1.4.10) | **Holds.** 0 of 24 screens scroll sideways. | One-off run at 320 × 640. |
| Tabs (4.1.2, 2.1.1) | **Holds.** The tablist role, `aria-selected`, roving tabindex, and arrow keys that now move focus as well as selection. The overflow arrows are mouse helpers (`tabIndex=-1`): keyboard users reach every tab with the arrow keys. | Flow *Tabs: …*. |
| Sample player (R13) | **Accessible by construction.** One button with `aria-pressed`, a label that names the stack and the length ("Play the sample of …, 12 seconds"), and the words in a disclosure. | Flow *Voice samples: …*. |

## Not verified

- A screen reader by ear (NVDA, VoiceOver, TalkBack). axe checks names and roles, not how a page sounds.
- Zoom to 200% on desktop (1.4.4), beyond the 320 px reflow run.
- Screens that are not on the list: sign-up and login, the Operator chat with a real model's cards, a live campaign's controls,
  and Insights with learning proposals. These need data the seeded workspace does not have.
- Hindi transcript lines are marked `lang="hi"`. They were not checked for pronunciation.
